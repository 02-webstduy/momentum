## 二、信息流 1：AI 总结 / 分解生成（本次核心）

**改动前**：前端 POST → handler 只收 GET 返回 405 → `AgentError("http")` → 永远走本地降级（`buildLocalSummary` / `localDecomposition`），`agent/client.ts` 里 219 行校验逻辑是死代码。

**改动后**：完整闭环，正常路径与降级路径并存。

```
TodayPage / DecomposePage
  └─ agent/client.ts  callAgent(action, input, 9s 超时)
       └─ POST /functions/v1/app   {action, input}
            └─ Sites Gateway（校验站点访问）→ functions/handler.ts
                 ├─ 方法/JSON/action/input 校验失败 → 4xx  {ok:false,error}
                 ├─ Deno.env 缺 LLM_API_KEY        → 503  {ok:false,error:"no_key"}
                 └─ OpenAI chat/completions（8s 超时, JSON mode）
                      ├─ 网络/超时/非 2xx/坏 JSON → 502  {ok:false,error:"upstream"}
                      └─ 成功 → {ok:true, data:<LLM 返回的 JSON>}
            └─ 响应回前端 agent/client.ts
                 ├─ 非 2xx → 按状态码分类 AgentError → 本地降级并标注
                 ├─ ok:false → AgentError("agent")    → 本地降级并标注
                 └─ ok:true → 客户端严格校验（≤120 字 / 禁感叹号 / 证据 ref 必须
                 │            属于当日真实事件 / nextStep 必须引用未完成里程碑）
                 ├─ 校验不过 → schema/tone 错误 → 本地降级并标注
                 └─ 校验通过 → 落库：DaySummary 快照 或 分解方案 + 冻结哈希
```

三个关键设计点：

1. **超时链 8s < 9s**：后端先超时返回 502，前端才能在 9s 内收到并自行兜底；若后端超时更晚，前端会先 abort，永远拿不到结构化错误。
2. **密钥流**：Sites Settings 填入 → 平台 Secret → 运行时 `Deno.env.get("LLM_API_KEY")`。不进仓库、不进前端产物、不出现在任何错误响应里。
3. **错误码契约**：后端只返回 `error` 码（`method_not_allowed` / `bad_json` / `unknown_action` / `missing_input` / `payload_too_large` / `no_key` / `upstream`），语义映射由前端 `errorForStatus` + `ok:false` 分支完成，后端不重复做业务校验——前端反正会再验一遍。

## 四、未变的不变量（本次刻意不碰）

- **确定性进度引擎**：AI 绝不参与进度计算，进度仍由纯函数现算、派生不落库。
- **前端校验层**：后端返回什么都会再过一遍严格校验，所以后端可以保持薄。
- **降级链**：Agent→本地模板、GitHub→手动录入的双保险原样保留，降级时显式标注来源。
- **冻结 + 哈希**：分解方案锁定与 SHA-256 前 8 位校验机制未动。
