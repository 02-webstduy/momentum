## 一、Qoder Sites 是什么

### 1.1 结论

Qoder Sites 是 Qoder 内置的「建站 + 预览 + 托管发布」能力，不是一台给你 IP 和端口的裸服务器。

你在本地项目目录里写代码，Qoder 负责把它打包成静态产物，发布到平台的托管地址上，并生成一个可分享的链接。整个过程不需要你购买云服务器、配置 Nginx、申请域名或做 HTTPS 证书。

它更接近「带发布能力的静态网站托管平台」，而不是 VPS：

| 对比项 | 传统服务器（IP + 端口） | Qoder Sites |
| --- | --- | --- |
| 访问方式 | `http://IP:端口` | 平台分配的站点链接（固定后缀，可改前缀） |
| 服务器运维 | 自己装环境、配防火墙、续证书 | 平台托管，无需运维 |
| 域名与 HTTPS | 自己购买和配置 | 平台提供地址，默认 HTTPS |
| 后端 | 自己部署数据库、接口 | 默认静态；可选 Functions、数据库、存储、Cloud Agent |
| 更新方式 | 自己传文件/重启服务 | 在 Qoder 中重新发布 |
| 访问控制 | 自己写鉴权或防火墙规则 | 站点级访问范围：仅自己 / 仅受邀 / 任何人 |

所以：**对访客来说它是一个普通网站**（浏览器打开一个链接即可）；**对开发者来说它不是一台服务器**，而是一套托管的建站与发布流程。

### 1.2 谁可以访问

分两个阶段：

1. **现在（本地预览）**
   - 只运行在这台电脑上：`http://127.0.0.1:5173/`。
   - 只有本机能打开；别人拿到这个地址也访问不到。
   - Qoder 的站点工作台可以在这里预览页面，但这不是公网发布。

2. **发布之后**
   - 新站点默认是「仅自己可访问」，不会因为发布就自动公开。
   - 可在站点设置中切换访问范围，常见三档：
     - 仅自己可见；
     - 仅受邀用户可见（按 Qoder 账号邮箱或 UID 添加）；
     - 任何人可访问（公开链接）。
   - 企业版通常限制为组织内可见，不能向组织外公开。
   - 具体档位和限制以发布界面的实际选项为准。

这一点很重要：**发布 ≠ 公开**。如果只是想让评委或朋友看到，需要显式把访问范围改成公开，或把对方加入受邀名单。

### 1.3 发布、更新与地址

- 发布时会生成站点地址，地址前缀可修改，后缀由平台固定。
- 发布前可以多次预览；预览不会自动替换线上版本。
- 修改代码后，需要重新发布，访客才能看到新版本。
- 平台按账号统计站点用量；达到额度时，新建站点或公开访问可能受限（以平台当前规则为准）。

### 1.4 本项目的实际使用范围

Momentum 目前只用了 Sites 的「本地预览 + 静态站点」部分：

- 没有创建云端草稿；
- 没有执行发布；
- 没有启用数据库、存储或 Cloud Agent 后端；
- 源码中的 `functions/` 目录仍是脚手架自带的示例函数，**不是可用的 AI 后端**（详见 2.7）。

也就是说，目前没有任何云端资源被创建或计费。

### 1.5 一个容易误解的点：公开后数据也不共享

Momentum 的数据全部存在**访问者自己的浏览器**里（IndexedDB，键名前缀 `momentum:v1:`）。

即使将来把站点设为公开：

- 每位访客看到的是自己浏览器里的数据；
- 新访客打开时是空状态，需要手动「加载演示数据」；
- 不会出现「一个人录入、所有人可见」的共享数据。

这是需求文档「纯前端、本地优先、不做云同步」的直接结果，不是缺陷。

### 2.2 技术架构

- React 19 + Vite 8 + TypeScript 5.9，构建为纯静态 `dist/`。
- 自写 history 路由，支持 `/`、`/project/:id`、`/decompose`、`/review` 深链。
- IndexedDB 为主要存储，localStorage 作为回退；演示数据、事件、锁定方案、归档、总结都在本地。
- 进度、健康度、趋势、DayFact 全部是确定性纯函数，AI 不参与任何百分比计算。
- AI 调用统一走同源 `/functions/v1/app`，前端不持有任何 API Key；失败时降级为明确标注的本地模板。
- 样式通过 `globals.css` 消费 `--site-*` 设计变量，已登记到 `.Momentum.qoder.site`。
- 源码约 7,600 行（`src/` 下 25 个文件）。

### 2.3 功能清单

#### 今日（`/`）

- 日期、连续活跃天数、有效工作段、关联仓库、今日提交数。
- 今日总结卡片：narrative、3 条 highlights、下一步、阻塞、证据 chips。
- 任意 highlight 或证据 chip 可点开，查看原始事件（提交哈希、时间、仓库、归因、置信度）。
- 手动补录一句话，自动归入项目/阶段，无法匹配时归入「未归类」。
- 事件归因可一键纠正，纠正结果优先于自动归因。
- 空状态：无数据时只显示「今天还没有自动采集到数据」和手动输入框，不生成 AI 内容。
- 里程碑达成时的 Cheer 卡片，只出现一次，可关闭。
- 「加载演示数据 / 清除本地数据」入口，演示数据全程标注。
- GitHub 采集入口、可选只读 Token、JSON 导入、30 分钟缓存说明。

#### 项目进度（`/project/:id`）

- 主进度条 + 百分比 + 健康度（超前/正常/滞后）+ 7 日趋势。
- 时间进度对照与「今天应到」刻度。
- 阶段列表：每阶段完成度，展开显示里程碑。
- 里程碑卡：手动三态、metric 型「还差 X」、目标日、达成时间。
- 边界处理：无里程碑显示「未设置里程碑」；目标日缺失显示「—」；权重全为 0 给出提示。
- 锁定卡：目标 → 阶段权重链、锁定时间、SHA-256 前 8 位哈希。
- 历史版本入口，可查看归档的旧方案。

#### 分解（`/decompose`）

- 三步：填写目标 → 生成方案 → 编辑并锁定。
- 项目选择与新建项目。
- Cloud Agent 生成；不可用时自动改用本地模板，并明确标注「内容不来自 AI」。
- 编辑：改名、调权重、删除/新增里程碑、上移/下移、删除/新增阶段。
- 校验：4–7 个阶段、每阶段 2–4 个里程碑、权重 1–10、metric 与 manual 混合。
- 锁定：规范化 JSON 的 SHA-256 前 8 位，写入锁定时间与版本，方案转为只读。
- 重新推导：二次确认、勾选确认后才能继续、生成 v2、归档 v1、展示新旧对比。
- 锁定后没有任何「生成」入口能改动方案；AI 只能在显式重新推导时产生草稿。

#### 回顾（`/review`）

- 7 天 / 30 天热力图，周一在上。
- 点击日期查看当天工作段、提交、关联仓库、连续活跃与总结。
- 历史总结列表（可展开），含叙事、高亮、下一步、阻塞、证据。
- 里程碑时间线：已达成与接下来，含目标日与「还差 X」。
- 证据弹窗与今日页共用。

### 2.7 尚未闭环 / 未验证的部分

这部分请重点看，避免把「预览可用」误认为「全部生产就绪」。

1. **真实 Cloud Agent 后端未实现**
   - 前端已经按同源 `/functions/v1/app` 的契约调用，并对超时、HTTP 错误、schema 不合规做了校验与降级。
   - 但 `functions/handler.ts` 目前仍是脚手架的示例（只接受 GET，返回 Hello），不能处理前端的 POST `{ action, input }`。
   - 因此在当前预览环境，AI 生成实际走的是**本地模板降级**，页面会明确标注「Cloud Agent 未连接」。
   - 要让 AI 真正调用 Qoder Cloud Agent，需要实现该 Function（使用 Sites 的 `qoder` 能力与平台托管的 `QODER_PAT`），并重新发布。这一步会引入后端资源，与「纯前端、无后端」的字面约束存在张力，需求文档对此的表述是「AI 只走 Cloud Agent，可失败并降级」，当前实现选择了「前端契约 + 本地降级」这条安全路径。

2. **断网冷启动没有完全闭环**
   - 项目是纯静态 SPA，没有 Service Worker，也没有 PWA 缓存。
   - 已加载的页面断网可以继续使用；但浏览器完全离线后重新打开链接，是否能加载 HTML 取决于浏览器缓存，不能保证。
   - 如果需要严格满足「断网首屏无白屏」，应补一个 Service Worker 缓存应用壳，或在验收口径上明确为「无后端依赖、AI 失败不白屏」。

3. **真实 GitHub 拉取未联调**
   - 代码已实现 PushEvent 拉取、30 分钟缓存、限流与错误提示、可选 Token 本地保存。
   - 本次没有使用真实 GitHub 用户名和网络请求做端到端验证；演示数据是本地生成的。

4. **发布后的深链需要 SPA 回退**
   - 本地 Vite 开发服务器会自动回退到 `index.html`。
   - 发布到静态托管时，需要在准备阶段声明 SPA 回退（`spa: true`），否则直接打开 `/project/p-demo` 这类深链可能 404。

5. **AI 证据校验的严格程度**
   - 客户端已校验：证据 ref 必须属于当日真实事件、证据数量不少于 highlights、nextStep 必须包含未完成里程碑、narrative 不超过 120 字、语气禁用词、blockers 无证据则必须为空。
   - 尚未做到「每条 highlight 与某一条 evidence 一一绑定」的强制映射；UI 上每条高亮都能打开证据，但底层不是逐条签名关系。

6. **其他按设计存在的限制**
   - 数据只在本浏览器，换浏览器/设备/清缓存即丢失。
   - 演示数据是本地生成，不来自真实账号。
   - 未做多人协作、账号体系、云同步（需求明确不做）。
